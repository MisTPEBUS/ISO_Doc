# 修改密碼

## Route

```text
/change-password
```

## 目的

提供已登入使用者修改自己的密碼。

## UI

建議欄位：

- 目前密碼
- 新密碼
- 確認新密碼

## 基本行為

1. 使用者輸入目前密碼。
2. 輸入新密碼。
3. 再次輸入新密碼。
4. 前端確認兩次新密碼一致。
5. 呼叫後端修改密碼 API。
6. 顯示成功或錯誤訊息。

## 密碼政策（依 SPEC.md §5「Auth」）

- 至少 8 碼，不限定字元類別（不要求中英數混合）。
- 新密碼不可等於目前密碼。
- 兩次新密碼需一致。

前端驗證需與上述一致，不得自行加嚴或放寬；最終仍以後端回應為準。

## 錯誤處理

- 成功：`204`。
- 失敗一律 `400` + `ValidationProblemDetails`（例如 `errors.currentPassword`）。**目前密碼錯誤是 400，不是 401**，不可因此把使用者導回登入頁。
- 呼叫需帶 `X-CSRF-TOKEN`（見 `[未完善]-api-contract.md`）。
